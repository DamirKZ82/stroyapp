# Админка ToiApp

Веб-страница для того, кто следит за сервисом: кто зарегистрировался, какие
объявления появились, что с заявками и отзывами, не падает ли бэк. Отсюда же
разбирают жалобы, скрывают объявления, блокируют людей, назначают других
админов и заводят служебные входы для ревьюеров.

Адрес: **https://api.toiapp.kz/admin**

Открывается с компьютера и с телефона. Отдельного приложения и сборки нет:
это одна страница, которую отдаёт сам бэк.

## Девопсу

### Выложить эту версию

```bash
cd /opt/toyhana                 # где лежит проект
git pull
docker compose up -d --build backend
```

Больше ничего не нужно: новые колонки и таблицы создаются сами при старте
бэка (`db/migrations.sql`, применяется идемпотентно).

После этой выкладки **прежние входы в админку перестают работать**: каждый
админ один раз подтверждает номер по SMS и задаёт себе пароль (см. «Вход»).

Чтобы «Пожаловаться», «Заблокировать собеседника», шаг согласия с условиями
и «Написать в поддержку» появились у пользователей, нужна новая сборка
приложения. Сам бэк от старых сборок ничего нового не требует.

После выкладки стоит открыть https://api.toiapp.kz/terms — на эту страницу
ведёт новая сборка приложения.

### Первый админ и запасной выход

Админов назначают в самой админке. Скрипт нужен для самого первого админа
и на случай, когда войти в админку некому:

```bash
docker compose exec backend python -m scripts.make_admin +77XXXXXXXXX
```

Скрипт создаст пользователя, если его ещё нет. Доступа это ещё не даёт:
человек сам открывает `/admin`, подтверждает номер по SMS и задаёт пароль —
поэтому номер должен быть **настоящим**.

Снять права: тот же скрипт с `--revoke` в конце. Пароль при этом стирается.

### Адрес клиента

Лимит попыток входа считает адрес клиента по заголовку `X-Real-IP`, который
ставит наш nginx (`nginx/nginx.conf`). Если перед nginx появится ещё один
прокси или CDN, в `X-Real-IP` должен приходить настоящий адрес клиента —
иначе лимит по адресу просто не применяется (лимит по номеру остаётся).

## Вход

**Обычный вход** — номер телефона и пароль. SMS не нужна.

**Первый вход и забытый пароль** — «Подтвердить номер по SMS»: номер, код из
SMS, затем свой пароль (два раза). Дальше — снова по номеру и паролю. Тем же
путём пароль меняют; все открытые входы в админку при этом закрываются.

Код здесь свой — **шесть цифр**, в SMS так и написано: «kod … dlya parolya
adminki». Код входа в приложение (четыре цифры) для админки не годится. На
номер, который не назначен админом, SMS не приходит, хотя страница отвечает
так же: по ней нельзя узнать, кто у нас админ.

Пароль: не короче 8 символов, не из одних цифр, не из самых частых и без
своего номера телефона. Знает его только сам админ: другие админы пароль не
видят и задать за него не могут.

Вход живёт до закрытия вкладки, но не дольше 12 часов, и у каждой вкладки
он свой: запись, открытая в новой вкладке (и ссылка из Telegram), сначала
попросит войти. Браузер предложит сохранить пароль — на своём компьютере это
удобно, вход тогда в одно нажатие.

## Администраторы

**Назначить.** «Пользователи» → «Добавить админа»: номер телефона, имя (если
человек ещё не пользовался приложением) и свой пароль для подтверждения. Или
в карточке пользователя — «Сделать админом».

Назначенный получает метку «Админ · не активирован». Доступ включает **он
сам**: открывает `/admin`, нажимает «Подтвердить номер по SMS», вводит код и
задаёт пароль. Пока он этого не сделал, в админку его не пускает.

**Снять права.** В карточке админа — «Снять права админа», тоже со своим
паролем. Доступ пропадает сразу, пароль стирается; аккаунт в приложении
остаётся. С самого себя права снять нельзя — это делает другой админ.

**Кого назначить нельзя:** служебный аккаунт (он входит по коду из четырёх
цифр, который видят другие админы), заблокированного пользователя и
демо-номер из `REVIEW_PHONE`.

В карточке админа видно, когда он задал пароль и когда последний раз входил.
Назначение, снятие и смена пароля пишутся в «Действия» и приходят в Telegram
(если он настроен) — чужая смена пароля не пройдёт незаметно.

## Разделы

| Раздел | Что там |
|---|---|
| **Обзор** | Сколько новых жалоб, пользователей, залов, исполнителей, заявок, отзывов; сколько ошибок за сутки; регистрации, заявки и новые объявления по дням за две недели. Карточки ведут в свои разделы. |
| **Жалобы** | Жалобы из приложения на объявления, отзывы и собеседников. Число новых — прямо на вкладке. См. «Жалобы» ниже. |
| **Пользователи** | Поиск по телефону и имени, отбор «с объявлениями / с заявками / заблокированные / админы / служебные». В карточке — объявления человека, его последние заявки и отзывы, сколько на него жалоб, сколько человек внесли его в чёрный список и принял ли он условия использования. Кнопки: заблокировать, разблокировать, удалить аккаунт, сделать админом, снять права админа. Сверху — «Добавить админа». |
| **Залы** | Поиск по залу, заведению, адресу и владельцу; отбор по городу и статусу. В карточке — фото, цены, описание, владелец. Кнопки: скрыть зал, скрыть всё заведение, вернуть, удалить фото. |
| **Исполнители** | То же для тамады, артистов, фотографов и остальных категорий. |
| **Заявки** | Все заявки с поиском и отбором по статусу. Только просмотр. |
| **Отзывы** | Поиск по тексту, объявлению и автору, отбор по оценке. Отзыв можно удалить. |
| **Журнал ошибок** | Сбои бэка (с трассировкой), ошибки, которые прислали телефоны, и отказы — ответы «нельзя» и «не найдено». |
| **Действия** | Кто из админов что скрыл, заблокировал или удалил, какую жалобу закрыл, кого назначил админом — когда и почему. |
| **Служебные** | Входы без SMS для ревьюеров сторов и своих проверок. |

Телефон в поиске можно вставлять в любом виде: `+7 701 123 45 67`,
`8 (701) 123-45-67`, `7011234567` или его часть.

Страницей можно пользоваться с клавиатуры: первая остановка Tab —
«К содержимому», заголовок строки в любом списке — ссылка (Ctrl / ⌘ + нажатие
открывает запись в новой вкладке — там понадобится войти). У записи есть
свой адрес: `/admin#complaints/41`, `/admin#users/57`, `/admin#halls/12`.

## Жалобы

В приложении есть «Пожаловаться»: на карточке зала и исполнителя (внизу), у
каждого отзыва и в переписке — в меню под тремя точками вверху. Человек
выбирает причину и, если хочет, пишет комментарий. Жаловаться можно только
войдя; на своё — нельзя; больше 20 жалоб в сутки от одного человека сервер не
принимает.

О новой жалобе приходит сообщение в Telegram (если он настроен): номер, на
что она, причина и ссылка прямо на неё. Названия объявления и текста жалобы
в сообщении нет намеренно — их пишут пользователи. В разделе «Жалобы» по
умолчанию показаны новые.

**Сама жалоба ничего не меняет.** Порядок такой:

1. Открыть жалобу: видно, на что она, причина, комментарий, кто пожаловался
   и на кого. Объявление и обоих людей можно открыть прямо отсюда.
2. Решить, что делать: скрыть объявление, удалить отзыв (кнопка есть в самой
   жалобе), заблокировать человека — или ничего.
3. Закрыть жалобу: **«Меры приняты»** или **«Отклонить жалобу»**, с пометкой
   для других админов. Если на то же самое есть ещё новые жалобы, их можно
   закрыть тем же решением одной галочкой: у «Меры приняты» она уже стоит, у
   «Отклонить» — нет (отклонять не глядя не стоит). Закроются только те
   жалобы, что были, когда вы открыли карточку: пришедшая позже останется
   новой. Встречные жалобы двух собеседников друг на друга — разные жалобы,
   вместе они не закрываются.

В жалобе лежит снимок: название объявления и текст отзыва на момент жалобы.
Если владелец потом переписал или удалил объявление, видно, на что именно
жаловались.

**Переписку к жалобе не прикладываем.** По жалобе на собеседника видно, кто
на кого пожаловался, о каком объявлении шёл разговор и что написал
заявитель; сами сообщения админка по-прежнему не показывает.

Заявителю о решении никто не сообщает — уведомлений в приложении пока нет.
Жалобы удаляются вместе с аккаунтом того, кто их подал, и того, на кого они
поданы. Если удалился владелец объявления, а жалоба была на чужой отзыв к
нему, жалоба остаётся, но название объявления из неё стирается.

## Чёрные списки собеседников

В приложении вверху переписки есть меню — кнопка с тремя точками, — а в нём
«Заблокировать собеседника»; там же теперь и «Пожаловаться на собеседника».
Блокировка относится к человеку, а не к одной переписке: после неё двое не
могут писать друг другу — ни здесь, ни в других переписках — и отправлять
друг другу новые заявки. У того, кто заблокировал, все переписки с этим
человеком пропадают из списка.

Заблокированному приложение о блокировке прямо не сообщает: его список
переписок не меняется, а вместо поля ввода он видит «Написать этому
собеседнику сейчас нельзя».

**Снять блокировку** может только тот, кто её поставил: в профиле, в разделе
«Заблокированные», или в самой переписке. Переписка открывается из того же
раздела — нажатием на человека: в ней остаётся вся история, оттуда же можно
пожаловаться.

**Это не «Заблокировать человека».** В админке такая блокировка и называется
иначе — чёрным списком. Пользователь ведёт его сам и только для себя, и с
аккаунтом того, кого он заблокировал, ничего не происходит: человек входит
как обычно, его объявления остаются в поиске, с остальными он переписывается
как раньше. Закрыть вход и убрать объявления может только админ — об этом
следующий раздел.

**Что остаётся как было.** Заявки, поданные до блокировки, работают: их
можно подтвердить, отклонить и отменить. Одно отличие: если владелец
отклоняет заявку клиента, который его заблокировал, написанная им причина
клиенту не показывается — ни в уведомлении, ни в самой заявке, — пока
блокировка стоит. Прежние сообщения не удаляются. Отзывы блокировка не
затрагивает, а пожаловаться на собеседника можно и после неё.

**Что видит админ.** Списка «кто кого заблокировал» в админке нет — как нет
и самой переписки. В карточке пользователя есть строка «Чёрные списки» с
двумя числами: «в чёрном списке у N чел. · сам внёс M» — сколько человек
заблокировали его и скольких заблокировал он сам.

О новой блокировке приходит сообщение в Telegram (если он настроен):
порядковые номера двух аккаунтов и ссылка на карточку того, кого
заблокировали. Имён, телефонов и текстов в нём нет. Если один человек
блокирует многих подряд, сообщений о его блокировках придёт не больше
нескольких в сутки; о разблокировке не приходит ничего. Делать по такому
сообщению ничего не нужно, но если одного человека вносят в чёрный список
многие — на него стоит посмотреть.

Записи чёрных списков удаляются вместе с аккаунтом любого из двоих.

Чтобы «Заблокировать собеседника» появилось у пользователей, нужна новая
сборка приложения. Сервер соблюдает блокировку и для старых сборок: тот,
кого заблокировали, при попытке написать получит отказ.

## Условия использования, фильтр брани и поддержка

Три вещи, которых магазины приложений ждут от сервиса с перепиской и
отзывами, — вместе с жалобами и блокировкой собеседника.

**Условия использования.** Страница https://api.toiapp.kz/terms: что
запрещено (оскорбления, угрозы, непристойное, обман, спам), что жалобы
рассматриваются за 24 часа и что нарушителей блокируют. При входе
приложение показывает шаг согласия: коротко о запретах, ссылки на условия и
на политику конфиденциальности, кнопки «Принимаю условия» и «Не принимаю».
Пока человек не принял условия, он остаётся гостем: каталог смотреть можно,
писать, бронировать и размещать объявления — нет. Тому, кто вошёл раньше,
чем появился этот шаг, приложение покажет его при следующем запуске.

В карточке пользователя есть строка «Условия использования»: когда и какую
версию он принял, или «не приняты». «Не приняты» будет у всех, кто
пользуется прежней сборкой приложения, — это не нарушение.

У демо-номера для проверяющих магазинов и у служебных аккаунтов согласие
сбрасывается при каждом входе: шаг с условиями они видят всякий раз, как
видит его новый человек. Иначе проверяющий, вошедший после нас, этого шага
не увидел бы — а его и проверяют. В карточке у них поэтому чаще всего «не
приняты».

Срок в 24 часа — обещание, записанное в условиях: за сутки жалобу нужно
открыть и принять по ней решение. О новых жалобах приходит сообщение в
Telegram.

Если условия меняются по существу: поправить текст в
`toiapp-back/static/terms.html`, поднять версию в шапке страницы и в
`services/terms.py` (`TERMS_VERSION`) — после выкладки приложение попросит
каждого принять новую версию. Опечатка или уточнение формулировки версию не
меняют.

**Фильтр брани.** Мат и его производные, расхожая транслитерация, грубые
английские слова, несколько казахских и оскорбления по национальности
закрываются звёздочками — в сообщениях, комментариях к заявкам и причинах
отказа, в отзывах и ответах на них, в названиях, адресах и описаниях
объявлений (включая поле телефона) и в именах. Текст не отклоняется:
сообщение доходит, отзыв публикуется, только без этих слов. Работает на
сервере, поэтому действует и для прежних сборок приложения. Написанное
раньше не переписывается.
Комментарий к жалобе фильтр не трогает: модератору нужны слова как есть.

Обычные обидные слова («дурак», «козёл») и брань, разбитую пробелами или
точками, фильтр не ловит — для этого есть «Пожаловаться». Список слов — в
`toiapp-back/libs/text_filter.py`; после правки запускают
`python -m scripts.check_text_filter` из `toiapp-back`: там примеры, которые
должны закрываться, и обычные слова, которые закрываться не должны.

**Поддержка.** В профиле приложения — у гостя тоже — есть «Написать в
поддержку»: открывает письмо на supporttoiapp@gmail.com, адрес виден в самой
строке. Тот же адрес стоит в условиях, в политике конфиденциальности и в
сообщении, которое видит заблокированный. Эту почту нужно читать.

## Что делать с плохим объявлением или человеком

Три средства, от мягкого к необратимому.

**Скрыть объявление.** Оно пропадает из поиска и из избранного у тех, кто
его туда добавил; карточка по ссылке не открывается, новые заявки и
переписки по нему не создаются. Уже поданные заявки и начатые переписки
остаются. Владелец видит его у себя «снятым с публикации», может править
(например, убрать чужие фото), но опубликовать сам не может: приложение
покажет ему причину, которую вы указали, и адрес поддержки. Возвращается
одной кнопкой — в то состояние, в каком было до скрытия.

Скрыть можно и **всё заведение** сразу: тогда не видны все его залы, включая
те, что владелец добавит позже. Причину скрытия заведения приложение
владельцу не показывает — её стоит сообщить ему отдельно.

**Заблокировать человека.** Вход закрывается, уже открытые сессии перестают
работать, все его объявления пропадают из поиска. Разблокировка возвращает
всё как было; объявления, которые вы скрыли отдельно и раньше, остаются
скрытыми. Причину блокировки видят только админы — человеку приложение
говорит, что аккаунт заблокирован, и даёт адрес поддержки.

**Удалить аккаунт.** Насовсем, вместе с объявлениями, фото, заявками,
переписками, отзывами и избранным — и с тем, что другие люди оставили на его
объявлениях. Вернуть можно только из бэкапа базы (см. `README-deploy.md`).
Для подтверждения нужно набрать слово «УДАЛИТЬ».

Отдельно можно удалить **одно фото** из объявления и **один отзыв** — тоже
насовсем. Текст удалённого отзыва остаётся в разделе «Действия», а оставить
новый отзыв по той же заявке автор уже не сможет.

## Журнал действий и удалённые аккаунты

Раздел «Действия» хранит, кто из админов что сделал, когда и почему. Пока
аккаунт человека существует, в записи видно, о ком она: номер, имя, название
объявления. Когда человек удаляет аккаунт — сам, из приложения, или это
делает админ — эти данные из всех записей о нём стираются. Остаётся «скрыл
зал», дата и причина, а вместо имени — «аккаунт №…». Так журнал не расходится
с обещанием на странице удаления аккаунта: после удаления номер и имя не
хранятся нигде.

## Служебные аккаунты

Обычный пользователь приложения, который входит по постоянному коду без SMS.

1. **Новый аккаунт**: телефон, имя (например `Google Play review`),
   код из 4 цифр (если оставить пустым, сгенерируется).
2. В приложении войти с этим номером и кодом. SMS не придёт.

У каждого аккаунта есть **Сменить код** (старый сразу перестаёт работать) и
**Отключить** — это та же блокировка, что у обычных пользователей: вход
закрыт, объявления аккаунта скрыты. Нажатие на номер открывает карточку
аккаунта; удалить его можно оттуда.

Права админа служебному аккаунту не выдаются: откажут и админка, и
`make_admin`. Иначе админом стал бы аккаунт, в который входят по коду из
четырёх цифр, а этот код видят другие админы.

**После ревью служебные аккаунты лучше отключать или менять им код:**
постоянный код при упорном переборе со временем угадывается.

## Ограничения, заложенные специально

- **Переписку пользователей админка не показывает.** Это личные сообщения;
  видны только счётчики.
- **Одно объявление удалить нельзя — только скрыть.** Насовсем объявления
  удаляет владелец или админ вместе с аккаунтом.
- **Админа нельзя заблокировать или удалить одним нажатием**, и себя тоже.
  Сначала с него снимают права админа — а это требует своего пароля.
- **Назначить и снять админа можно только со своим паролем.** Открытая на
  чужом компьютере вкладка сама по себе новых админов не заведёт.
- **Пароль другого админа нельзя ни увидеть, ни задать.** Забывший пароль
  сам подтверждает номер по SMS и задаёт новый.
- **Заявки — только просмотр.** Отвечает на заявку владелец, отменяет клиент.
- **Номер обычного пользователя сделать служебным нельзя.** Иначе админ
  получил бы вход в чужой аккаунт по известному коду. Номер из
  `REVIEW_PHONE` тоже нельзя: у него свой код из `.env`.
- Города, категории, удобства и типы мероприятий из админки не меняются:
  они заданы в коде бэка.
- **В журнале сбоев сервера запрос показан без значений** — только его
  форма. В самих запросах бывает текст личных сообщений.

## Чего пока нет

- Уведомлений админу о новых объявлениях. Новые видны сверху списков и на
  графике «Новые объявления» в обзоре.
- Ответа заявителю о том, чем кончилась его жалоба.
- Смены пароля изнутри админки: пароль меняют со страницы входа, через SMS.

## Как это устроено

- Страница — `toiapp-back/static/admin.html`, `admin.css`, `admin.js`, без
  сборки и сторонних библиотек. Отдаётся с запретом на кэш, на встраивание
  во фрейм и на любые скрипты и картинки с чужих адресов.
- Ручки — `/admin/api/*` в `routers/r90_admin.py`, `r91_admin_users.py`,
  `r92_admin_content.py`, `r93_admin_complaints.py`, `r94_admin_access.py`.
  Все, кроме самого входа, требуют токен админки: его выдаёт вход по паролю,
  живёт он 12 часов. Обычный токен приложения в админку не пускает даже
  админа, а токен админки не пускает в приложение. Третий вид токена —
  «пароля»: его выдаёт шестизначный код из SMS, живёт он 15 минут и годится
  для одного — задать пароль (`libs/auth.py`).
- Пароль хранится хэшем scrypt в отдельной таблице `admin_credentials`
  (`libs/passwords.py`, `services/admin_access.py`). Смена пароля меняет
  `session_version`, и все прежние токены админки перестают работать. Номер
  берётся из счётчика в базе и не повторяется — вход, выданный до снятия
  прав, не оживает после повторного назначения.
- Жалобы — таблица `complaints`, приём в `routers/r34_complaints.py`, правила
  в `services/complaints.py`.
- Чёрные списки собеседников — таблица `peer_blocks`, правила в
  `services/peer_blocks.py`, ручки приложения в `routers/r35_peer_blocks.py`:
  `POST` и `DELETE /chats/{guid}/peer-block`, `GET /peer-blocks`,
  `DELETE /peer-blocks/{guid}`. Строка таблицы — «кто кого заблокировал»;
  разблокировка её удаляет. В коде это везде слово `peer` («собеседник») —
  чтобы не путать с блокировкой аккаунта из `services/moderation.py`.
- Согласие с условиями — таблица `terms_acceptances` («кто какую версию и
  когда принял») и `services/terms.py`. Приложение узнаёт о нём по полям
  `terms_accepted` и `terms_version` в ответах входа и профиля и ставит его
  запросом `POST /profile/terms {version}`: версия — та, что человеку
  показали; если на сервере уже другая, ответ 409 и согласие не
  записывается. Сервер согласия не требует — только хранит: прежние
  сборки приложения о нём не знают, и отказ закрыл бы их пользователям
  переписку и заявки.
- Фильтр брани — `libs/text_filter.py`. К полям запросов подключён типом
  `Clean` (в роутерах объявлений, заявок, отзывов и профиля), к сообщениям
  чата — вызовом `hide`. `Clean` заодно убирает из текста то, что не примет
  база, и отказывает тексту длиннее 10 000 знаков — до фильтра, чтобы он не
  читал мегабайты.
- Любая строка попадает в запрос через `fit_to_sql` (`libs/common.py`), и он
  вычищает из неё нулевой байт и «половинки» суррогатных пар (`clean_text`).
  Это не косметика: запрос с такой «половинкой» asyncpg обрывает, не вернув
  соединение в пул, и десять таких запросов — даже без входа — оставляли
  воркер без соединений. Вторая линия — `_sendable` в
  `connections/connect_postgres.py`; там же предел ожидания свободного
  соединения (10 секунд), чтобы занятый пул давал отказ, а не молчаливое
  зависание. Такой отказ («Нет свободного соединения с базой») в
  `errors_back` не пишется — запись ждала бы того же пула; он остаётся
  строкой в логе контейнера и сообщением в Telegram, не чаще раза в минуту.
  Когда все соединения заняты, записи в `warns` и `errors_back` ждут
  свободного не дольше секунды; несохранённое остаётся в логе контейнера
  целиком — отказ с кодом, путём и пользователем, сбой с запросом и
  трассировкой.
- Скрытие и блокировка — `services/moderation.py`. Скрытое объявление — это
  `is_active = false` плюс отметка `hidden_at`; поиск, карточка, заявки и
  чаты смотрят на тот же `is_active`, что и раньше, избранное — на
  `hidden_at`.
- Каждое изменение пишется в таблицу `admin_actions`. В `subject_user_ids`
  записано, чьи данные в записи; по ним `services/account.py` обезличивает
  её при удалении аккаунта.
- `db/migrations.sql` применяется при каждом старте каждым воркером. В начале
  файла — очередь (`pg_advisory_xact_lock`), а новые колонки добавляются
  только при первом запуске: иначе миграция мешала бы живым запросам.

## Защита от перебора

Все лимиты считаются прежде всего на пару «номер + адрес, с которого
пришли». Тот, кто знает номер админа, свой счёт исчерпывает сам, а счёт
самого админа — нет: запереть его неудачными входами или запросами кодов с
одного адреса нельзя.

**Пароль админки.** За 15 минут — не больше пяти неудачных попыток на один
номер с одного адреса. Сверху два потолка: 30 неудач на номер со всех
адресов и 20 неудач с одного адреса по всем номерам. Потолок «на номер» не
касается адреса, с которого этот пароль уже вводили верно (сервер помнит
такие адреса три месяца и забывает при смене пароля): подбор с десятка чужих
адресов не закрывает вход самому хозяину пароля. Когда адрес клиента серверу
не виден, счёт идёт просто по номеру — пять попыток. Запертый вход
открывается сам через 15 минут или сразу — подтверждением номера по SMS и
новым паролем. Ответ на неудачный вход всегда один — «Неверный номер или
пароль»: по нему не понять, есть ли у номера доступ.

Свой пароль при назначении и снятии админа считается отдельно: неудачными
входами «с улицы» этот счёт не занять.

**Код из SMS для пароля админки** — шесть цифр, действует 5 минут:

- проверить код может только тот, кто его запросил (страница получает на
  запрос «талон» и предъявляет его вместе с кодом): посторонний не потратит
  попытки чужого кода и не погасит его своим запросом;
- 5 попыток на один код, потом код гасится;
- 1 запрос кода в минуту и 5 в сутки на номер с одного адреса; не больше 15
  кодов в сутки на номер со всех адресов (это и потолок расхода на SMS) и не
  больше 10 в сутки с одного адреса на все номера.

О каждом запросе кода, о каждой смене пароля, о назначении и снятии админа
приходит сообщение в Telegram (если он настроен) — чужая попытка не пройдёт
незаметно. Имя админа в таком сообщении — только буквы; номер — последние
четыре цифры.

**Код входа в приложение** — четыре цифры, 5 попыток на код, не больше 5
кодов в час на номер. В админку он не ведёт никак: ни войти, ни задать
пароль с ним нельзя. И наоборот: токен админки не открывает приложение.
